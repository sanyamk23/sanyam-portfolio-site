20 GitHub repos every vibecoder should install

Twenty open source repos for building apps and websites with Claude: security scanners, auth, a database layer, self-hosted deploys and analytics, and the add-ons that make Claude Code better. One prompt that sets them all up, then a short breakdown of each.

This is the page for anyone who commented REPO. The prompt is right below. Paste it into Claude Code opened in your project. It checks what you already have, shows you a plan for all twenty, and installs only what you say yes to. A few of these live on GitHub or on a server instead of in your code, and for those it tells you exactly what to do.
Paste into Claude
My app is: [one line on what it does, and the stack: framework, host, database, auth].

Set up the 20 tools below for this project. Start by checking what's already here: package.json and the lockfile, any auth or ORM in use, .github/workflows, the .claude folder and CLAUDE.md, and which of these CLIs are already on my machine. Then give me a plan before you install anything. For each tool: whether it fits this project and why, where it goes (my machine, this repo, GitHub, or a separate server), the exact command, and anything I have to do myself, like adding a secret or clicking through a dashboard. Wait for my OK. Then install what I approved one at a time, and run the project's checks after anything that touches the code.

Rules:
- Never print, paste or commit an API key or secret. When one is needed, tell me its name and where it goes (.env or GitHub repo secrets) and I'll add it.
- Don't replace auth or a database layer the project already has. If it has one, skip Better Auth or Drizzle and tell me why.
- Pin every GitHub Action you add to a full commit SHA, with the version in a comment.
- Nothing runs against production. ZAP only scans localhost or a staging URL I confirm I own.
- Coolify and Umami go on a server, not in this repo. Write me the steps and don't run them here.
- If a command fails or the docs have changed, read the repo's README and tell me before you try something else.

The 20:

1. Gitleaks (github.com/gitleaks/gitleaks). Install it, then run `gitleaks git -v` on the full history and `gitleaks dir -v .` on the working tree. Show me every finding before you do anything else, and tell me which provider each real key belongs to so I can rotate it. Then add it as a pre-commit hook.
2. Claude Code Security Review (github.com/anthropics/claude-code-security-review). Add its workflow as .github/workflows/security-review.yml, reading the key from a CLAUDE_API_KEY repo secret. If the repo is public, remind me to require approval for workflows from outside contributors.
3. Chrome DevTools MCP (github.com/ChromeDevTools/chrome-devtools-mcp). Run `claude mcp add chrome-devtools --scope user npx chrome-devtools-mcp@latest`. After I restart Claude Code, open my dev server in it and report any console errors or failed network requests.
4. Better Auth (github.com/better-auth/better-auth). Only if there's no auth yet. Run `npm install better-auth`, tell me to generate BETTER_AUTH_SECRET with `openssl rand -base64 32` and add it myself, set BETTER_AUTH_URL, use the adapter for my database (Drizzle if we're adding it), and generate the tables with `npx auth@latest generate`.
5. tweakcn (github.com/jnsahaj/tweakcn). Only if the project uses shadcn/ui. Nothing to install yet. Tell me to pick a theme at tweakcn.com and paste you the `npx shadcn@latest add` command it gives me.
6. Claude Code Action (github.com/anthropics/claude-code-action). Tell me to type /install-github-app in Claude Code. It needs me to be an admin on the repo.
7. Coolify (github.com/coollabsio/coolify). Write me the steps for a separate VPS: the install command from the README, run as root, with the root user set through the install variables in the docs so the open signup page never appears. Then pointing a domain at it with HTTPS, and connecting this repo.
8. Trivy (github.com/aquasecurity/trivy). Install it with brew or from the official releases page, and never v0.69.4. Run `trivy fs .` and report the high and critical findings with the version that fixes each.
9. Umami (github.com/umami-software/umami). Plan it as a service on the Coolify server, or Umami Cloud if I don't want a server. Remind me the default login is admin / umami and has to be changed first. When I give you the website ID, add the tracking script to the root layout.
10. ccusage (github.com/ccusage/ccusage). Nothing to install. Run `npx ccusage@latest daily` and show me the table.
11. Mem0 (github.com/mem0ai/mem0). Only if the app has an AI feature that talks to users. Don't install it yet. Tell me where it would plug in and what it would remember.
12. OpenSpec (github.com/Fission-AI/OpenSpec). Run `npm install -g @fission-ai/openspec@latest` (it needs Node 22.12 or newer), then `openspec init` in this project.
13. Semgrep (github.com/semgrep/semgrep). Install it with `pipx install semgrep` or `uv tool install semgrep`, run `semgrep scan --config auto`, and report the findings grouped by file. Don't fix anything yet.
14. ZAP (github.com/zaproxy/zaproxy). With my dev server running, run the baseline scan: `docker run -t ghcr.io/zaproxy/zaproxy:stable zap-baseline.py -t http://host.docker.internal:[port]`. Report each warning and what the fix would change.
15. Drizzle (github.com/drizzle-team/drizzle-orm). Only if the project uses a SQL database with no ORM. Install drizzle-orm, drizzle-kit as a dev dependency, and the driver for my database, write drizzle.config.ts, and pull the existing schema with `drizzle-kit pull`. Never run a migration against anything but my local database.
16. React Bits (github.com/DavidHDev/react-bits). Only if the app is React. Add `"@react-bits": "https://reactbits.dev/r/{name}.json"` under registries in components.json, so components install with `npx shadcn@latest add @react-bits/<Name>`. Don't add any components until I ask, and any you add must respect reduced motion.
17. Claude Squad (github.com/smtg-ai/claude-squad). Check that tmux and gh are installed, then install it the way the README shows for my OS, so it runs as `cs`.
18. Marketing Skills (github.com/coreyhaines31/marketingskills). Run `npx skills add coreyhaines31/marketingskills`.
19. OWASP Cheat Sheets (cheatsheetseries.owasp.org). Nothing to install. Add this line to CLAUDE.md: "Before writing code for auth, sessions, passwords, file uploads, input validation or user data, read the matching OWASP cheat sheet at cheatsheetseries.owasp.org and follow it."
20. Task Master (github.com/eyaltoledano/claude-task-master). Run `npm install -g task-master-ai` and `task-master init`, and set the main model to claude-code/sonnet so it runs on my Claude Code login instead of an API key. If I said yes to OpenSpec, ask me whether I still want this one.

When it's all done, give me a table: each tool, installed or skipped, where it lives, and anything still waiting on me.

Run it in Claude Code opened in your project, so it can see what you already have. It won't install all twenty on every project. A static website has no use for auth or a database layer, and an app that already runs on Supabase Auth shouldn't switch, so it tells you what it skipped and why.

Some of these overlap on purpose. Gitleaks, Semgrep, Trivy, ZAP and the Claude security review all look for problems, but each one looks at a different layer, and the breakdown says which. OpenSpec and Task Master both plan the work before Claude codes it, and you probably only want one of them per project.

1. Gitleaks: find the keys you already committed

Gitleaks scans your code and your whole git history for API keys, tokens and passwords. Deleting a key in a later commit doesn't remove it from the history, and anyone who can clone the repo can still read the old commit. Run it once on every repo you have, then add it as a pre-commit hook so the next key gets stopped before it's committed. If it finds a real key, rotate it at the provider, because removing it from the code leaves the old one working.

2. Claude Code Security Review: a security pass on every pull request

Anthropic's GitHub Action reads each pull request for security bugs like injection, broken auth, exposed data and XSS, and comments on the lines it's worried about. It only looks at what changed, and it filters out low-impact noise before it posts. It needs an Anthropic API key saved as a repo secret. Anthropic says it isn't hardened against prompt injection, so on a public repo turn on approval for workflows from outside contributors. The same review runs on your machine when you type /security-review in Claude Code.

3. Chrome DevTools MCP: let Claude open the browser

Google's MCP server gives Claude a real Chrome window. It can open your app, click through it, read the console, inspect network requests and record a performance trace. So instead of you copying an error out of the console and pasting it into the chat, Claude goes and looks. Claude can see everything in that browser, so don't log into anything personal in it. Google collects usage stats by default, and the --no-usage-statistics flag turns that off.

4. Better Auth: login that lives in your own code

An auth library for TypeScript that runs in your app and stores users in your own database. It's free and MIT licensed. Email and password, social logins, 2FA and organizations come built in or as plugins, and its CLI writes the database tables for you. If you already use Supabase Auth, Clerk or something else that works, leave it alone. Switching auth on a live app means migrating every user's account.

5. tweakcn: a shadcn theme that isn't the default

Sites built on shadcn/ui all look the same because most of them ship the default theme. tweakcn is a visual editor for it. You start from a preset or change the colors, radius, fonts and shadows while it previews real components, then copy one command that installs the theme into your project. There's nothing to install until you've picked one.

6. Claude Code Action: tag @claude on GitHub

This puts Claude in your GitHub repo. Mention @claude in an issue or a pull request and it answers questions about the code, reviews the change, or writes the fix on a branch. It runs on GitHub's machines, so it works while your laptop is closed. Set it up by typing /install-github-app inside Claude Code. You need to be an admin on the repo.

7. Coolify: your own Vercel on a server you rent

Coolify is an open source, self-hosted alternative to Vercel, Netlify and Heroku. You rent a VPS, run one install command, and get a dashboard that deploys from GitHub on every push, with SSL, databases and backups. You pay for the server, and there's no per-seat or per-build bill on top. The project recommends one server for Coolify itself and another for your apps.

Until someone creates the admin account, the signup page is open, and whoever registers first controls the server. Create the account the moment the install finishes, or set the root user in the install variables so the page never opens.

8. Trivy: known holes in your dependencies

Trivy, from Aqua Security, checks your dependencies, Docker images and infrastructure config against databases of known vulnerabilities, and looks for secrets while it's there. trivy fs . scans the project folder and tells you which version fixes each problem.

It's also the best lesson on this list. In March 2026 attackers used stolen credentials to publish a malicious Trivy release, v0.69.4, and moved almost every version tag of its GitHub Action to code that stole secrets from CI runs. It's tracked as CVE-2026-33634. That's why the prompt pins every GitHub Action to a commit SHA: someone with access can move a tag to new code, but a SHA always points at the same code.

9. Umami: analytics without Google

Open source analytics you can host yourself. It doesn't use cookies or collect personal data, which makes it a lot simpler to deal with under privacy law than Google Analytics. Run it on your Coolify server next to a Postgres database, or use Umami Cloud. The first login is admin with the password umami, so change that before you do anything else.

10. ccusage: what your Claude Code usage costs

Claude Code already keeps logs on your machine. ccusage reads them and shows how many tokens you used and what it would have cost on the API, by day, week, month or session. There's nothing to install: npx ccusage@latest. It also reads Codex, Gemini CLI, Copilot CLI and a dozen others.

11. Mem0: memory for the AI inside your app

Mem0 gives the AI features in your app a memory. It saves facts from conversations, like a user's preferences or what they asked about last week, and pulls the relevant ones back into the next prompt, so your chatbot remembers people between sessions. Use the library from npm or pip, host the server yourself, or use their cloud. Skip it until your app has an AI feature that talks to users.

12. OpenSpec: agree on the spec before the code

Spec-driven development for coding agents. Type /opsx:propose and a feature name, and it writes a proposal, the requirements, a design and a task list into openspec/changes/ for you to read before any code exists. /opsx:apply builds it, and /opsx:archive files the spec once it ships. The specs stay in the repo, so the next session can read why the code is the way it is.

13. Semgrep: bugs you can spot in the source

Semgrep reads your source code for patterns that are known bugs, like SQL built from strings, eval on user input or a hardcoded secret. semgrep scan --config auto picks rules for the languages it finds. The CLI is free and open source, and there's a Claude Code plugin (/plugin marketplace add semgrep/mcp-marketplace) that runs it on what Claude writes.

14. ZAP: test the live app from the outside

Semgrep reads your code. ZAP, which used to be OWASP ZAP, looks at your running app the way someone on the internet would, and reports things like missing security headers, cookies without the secure flags and error pages that leak details. The baseline scan only looks and doesn't attack, and it's one Docker command. Only point it at sites you own, because scanning someone else's site can get you in legal trouble.

15. Drizzle: a database layer Claude can check

A TypeScript ORM. You write your tables in TypeScript and query them with code that looks like SQL, with types all the way through. That gives Claude something to check its work against: if it queries a column that doesn't exist, the build fails before a user ever sees it. drizzle-kit writes the migrations. It works with Postgres, MySQL and SQLite, including Supabase and Neon, and Better Auth has an adapter for it.

16. React Bits: animated components you copy in

A free library of animated React components: text effects, backgrounds, cursors, galleries. Each one comes in JS or TypeScript and in CSS or Tailwind, and installs with the shadcn CLI, for example npx shadcn@latest add @react-bits/SplitText-TS-TW. It also works with the shadcn MCP server, so Claude can find and add components itself. Use one or two. A page where everything moves looks like a template.

17. Claude Squad: several Claude Codes at once

Claude Squad runs several Claude Code sessions in one terminal, each in its own git worktree on its own branch, so they never edit the same files. Put one on the bug, one on the feature and one on the tests, check in on each, and merge what works. It runs Codex, Gemini and Aider too. It needs tmux and the GitHub CLI, and once installed you start it with cs in your project.

18. Marketing Skills: 53 skills for after you ship

Corey Haines's set of 53 Claude Code skills for marketing: copywriting, conversion, SEO and AI search, pricing, launch plans, cold email, paywalls, analytics setup and more. Claude only reads a skill in full when the task matches it, so installing the whole set doesn't crowd every session. One command: npx skills add coreyhaines31/marketingskills.

19. OWASP Cheat Sheets: how to do the risky parts right

OWASP's free set of short pages on doing one security job properly: password storage, sessions, file uploads, JWTs, input validation and more than 130 others. There's nothing to install. The prompt adds one line to your CLAUDE.md telling Claude to read the matching cheat sheet before it writes code in those areas, so it follows the written standard instead of whatever it half remembers.

20. Task Master: a PRD turned into a task list

Task Master turns a PRD into a list of tasks with dependencies, then tells Claude which one to do next. Write what you're building in .taskmaster/docs/prd.txt, ask it to parse the PRD, and keep asking for the next task. It runs as a CLI or an MCP server, and set to claude-code/sonnet it uses your Claude Code login, so there's no extra API key. If you went with OpenSpec, you can skip this one.
