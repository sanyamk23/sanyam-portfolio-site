The Omega setup: Opus plans, Haiku agents do the work

The Claude Code setup from the video. Opus 5.5 on extra effort runs the job, Haiku 5.5 agents do the work for a fortieth of the price, every agent gets a goal and a check, memory gets compacted early, and the skills improve after every session. One prompt that sets it all up, then what each part does.

This is the page from the Omega video. The prompt is right below. Paste it into Claude Code opened in your project folder. It shows you every file before it writes it, and at the end it tells you the two settings you set by hand.
Paste into Claude Code
Set this project up as an orchestrator-and-workers system.

1. Create CLAUDE.md with: what this project is (ask me two questions if you can't tell from the files), the rules below, and a folder map. Create docs/progress.md, docs/decisions.md and docs/known-issues.md.
2. Rules for CLAUDE.md:
   - You (the main session) are the orchestrator. You plan, write briefs and check results. You don't do bulk work yourself when a worker can do it.
   - Workers are subagents on Haiku. Every brief states the goal, the files to read, and a "Done when:" check that can be run or seen.
   - Before accepting any worker's output, run its check yourself. If it fails, send it back with the failure. Never pass on a worker's report unchecked.
   - Start of every session: read CLAUDE.md and the three docs. End of every session: update progress.md, add new decisions and gotchas, and propose skill edits with the evidence from this session. I approve them before you apply them.
3. Create .claude/agents/builder.md (model: haiku; writes code to a brief, runs the check, reports what it ran) and .claude/agents/reviewer.md (model: haiku; reads a diff against a brief and lists what fails it).
4. Create .claude/skills/reflect/SKILL.md: at the end of a session, list what went wrong or took too long, propose the smallest edit to a skill or CLAUDE.md that would have prevented it, and wait for my OK.
5. Tell me the two settings to set by hand: /effort xhigh, and export CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=40 in my shell before launching Claude Code.

Show me every file before you write it.

Omega is my name for this setup. It isn't an Anthropic product, but the idea is theirs. Anthropic's own page for Haiku says: "A more intelligent model like Fable or Opus can plan the work and hand off subtasks to Haiku, making it practical to run many agents in parallel." Everything below is that sentence, set up so it runs the same way every session.

1. Opus 5.5 on extra effort is the boss

Type /model and pick Opus 5.5, then /effort and pick xhigh, the level I call extra effort in the video. To make it stick, put "effortLevel": "xhigh" in your settings.json. The boss plans the job, writes a brief for each worker and checks what comes back. It doesn't write the code itself.

2. Haiku 5.5 agents do the work

Each worker is a file in .claude/agents/ with model: haiku in its frontmatter. The prompt makes two, a builder and a reviewer, and you can add more the same way, one job each. If you'd rather every subagent run on Haiku, set the first line below in your shell before you launch. On its own it leaves the built-in Explore and Plan agents on your main model, and the second line moves them too.

Copy and paste
export CLAUDE_CODE_SUBAGENT_MODEL=haiku
export CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1
Copy and paste
---
name: builder
description: Writes code to a brief, runs the brief's check, reports what it ran.
model: haiku
---

You get a brief with a goal, the files to read and a "Done when:" check.
Do the work, run the check, and report the exact command you ran and its output.
If the check fails, say so. Don't report done until it passes.

3. Every agent gets a goal and a check

Every brief ends with "Done when:" and something you can run or see: a test that passes, a file that exists, a number on the screen. The boss reruns that check itself before it accepts the work. If it fails, the work goes back to the worker with the failure attached. That loop is why cheap agents don't hand you junk.

4. Compact at 40%, or 60% on big jobs

Claude gets worse at recalling things as its context fills up. Anthropic calls it context rot. Compacting early keeps the boss sharp. Run this in your shell before you start Claude Code, and use 60 instead of 40 for long builds:

Copy and paste
export CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=40

Lower numbers compact earlier. The setting can only make compaction happen sooner, never later, and it works for subagents too. Type /context during a session to see how full it is.

5. One folder system

Every agent reads the same map, so nobody goes looking for where things live. This is the layout the prompt sets up:

Copy and paste
CLAUDE.md               what this project is, the rules, where everything lives (read first, every session)
docs/progress.md        where we are: done, next, a dated log line per session
docs/decisions.md       what's settled, with the date and why
docs/known-issues.md    gotchas and their fixes
.claude/agents/         worker agents, each with model: haiku and one job
.claude/skills/         one folder per repeatable task, each with a SKILL.md

6. Skills that get better after every session

At the end of a session, the reflect skill lists what went wrong or took too long and proposes the smallest edit to a skill or to CLAUDE.md that would have stopped it. You read the edit and say yes or no. Nothing changes without your OK, so the skills only get better from things that actually happened.

What it costs

ModelInput, per million tokensOutput, per million tokens
Opus 5.5$4$20
Haiku 5.5$0.10$0.50

A Haiku token costs a fortieth of an Opus token. Haiku's price goes up to $0.50 and $2.50 on prompts over 100,000 tokens, which is one more reason to keep worker briefs short. More agents means more tokens in total. Anthropic measured multi-agent systems using about 15 times the tokens of a chat, so the saving is in the price of each token, not the count. The boss stays on Opus for the thinking, and the bulk of the tokens go through Haiku.

Claude Code also has a built-in version. Type /effort ultracode and, for every substantive task, Claude plans a workflow that runs many subagents from a script, dozens to hundreds per run and up to 16 at once by default. It doesn't change your effort level, and /effort ultracode off turns it back off.
